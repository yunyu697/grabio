# Grabio 界面设计规范

> 目的：让"每加一轮功能就把界面做乱、再回头调 UI"这件事在流程上不再发生。
> 颜色早已 token 化；本规范补齐**尺寸与排版层**（行高、间距、字体、字号、圆角、描边、控件高度），
> 并配一个可重复运行的检查，作为打 tag 前的必过项。

- 规范版本：v2（2026-11-15，阶梯收敛版）
- 适用代码：`src/styles.css`、`src/index.html`、`src/app.js`
- 检查脚本：[tools/Check-FwUiTokens.mjs](../tools/Check-FwUiTokens.mjs)
- 例外清单：[tools/fw-ui-tokens.exceptions.json](../tools/fw-ui-tokens.exceptions.json)（v2 起为空）
- 本轮扫描证据：[docs/evidence/ui-tokens/](evidence/ui-tokens/)

**v2 相对 v1 的变化**：不再给现状逐个命名。字号从 16 档收到 6 档、间距从 13 档收到 10 档
（4px 网格，删掉 2px 逐档）、行高从 5 档收到 4 档（1.55/1.65 并成 1.6）、圆角从 8 档收到 4 档、
控件高度从 9 档收到 4 档。并档会改变观感，所以这一版同时做了真实 Tauri 构建的多尺寸/多主题视觉验收。

## 0. 一句话规则

**界面上的颜色、字号、行高、间距、圆角、描边宽度、控件高度，只能写 `var(--token)`。
字面值只允许出现在 `src/styles.css` 顶部的 token 定义区。**

其余容器/装饰尺寸（缩略图、图标底板、表格列宽、内容区最大高度）允许字面值，
但每个角色只能取 6.1 节列出的固定档位，越界即 `role-size` 报错。

## 1. 强制范围与检查口径

| 类别 | 强制 | 说明 |
| --- | --- | --- |
| 颜色（含 rgba/rgb/hsl） | 是 | 必须在明暗 × 四套颜色主题里定义 |
| 字号、字体族 | 是 | 见第 3 节阶梯 |
| 行高 | 是 | 见第 3 节 |
| **角色选档** | 是 | 正文/标题/按钮/输入框/导航项/列表行只能落在自己的档位集合里，见第 3.4 节 |
| 内边距 / 外边距 / 间隙 / 定位偏移 | 是 | 见第 4 节 4px 网格 |
| 圆角 | 是 | 见第 5 节 |
| 描边宽度 | 是 | 只允许 1px / 1.5px / 滚动条内缩 3px |
| 控件高度 | 是 | 按钮、输入框、图标按钮、芯片、开关、选择器 |
| 行内样式里的字面值 | 是 | `style="…"` 只允许 `var()/calc()/%/0/auto` |
| 容器宽高、最大高度、栅格模板 | 是（角色档位） | 按角色锁定固定档位集合，见第 6.1 节；越界报 `role-size` |
| 图标 `width/height` 属性 | 是（白名单） | SVG 属性无法用变量，见第 8 节 |

检查脚本按上表判定，`error` 会让命令以退出码 1 结束。

**只用 token 不等于做对了。** 用了 `var(--fs-title)` 但把它写在一个正文段落上，仍然是错的：
第 3.4 节把每个角色的可选档位固定下来，检查脚本据此报 `role-font` / `role-height`。
同一角色只允许一个高度档时，这一条同时就是"同角色容器尺寸不一致"的检查。

## 2. 颜色与主题

### 2.1 两轴模型

- **明暗**：`html[data-theme="dark"|"light"]`
- **颜色主题**：`html[data-color="violet"|"azure"|"emerald"|"amber"]`
- 两轴叠加、互不覆盖；令牌名一致，只有取值不同。
- 首屏（JS 未执行）就是紫罗兰，默认值直接写在 `html[data-theme]` 块里。

新增颜色主题时：复制一整套 `html[data-color="x"][data-theme="dark|light"]` 块，
不要只覆盖 `--accent`——只覆盖强调色会让状态色、面板层级与背景脱节。

### 2.2 语义色

| token | 用途 |
| --- | --- |
| `--bg` / `--bg-2` | 窗口底色 / 侧栏与状态栏底色 |
| `--panel` / `--panel-2` / `--panel-3` | 卡片 / 次级块 / 悬浮与按下 |
| `--line` / `--line-2` | 主分隔线 / 次级分隔线 |
| `--fg` / `--fg-2` / `--fg-3` | 主文字 / 次要文字 / 弱化文字 |
| `--accent` / `--accent-2` | 强调色（文字、描边、图表） |
| `--accent-solid*` | 实心按钮底色及其 hover/active |
| `--ok` / `--warn` / `--err` / `--info` | 状态色（成功/警告/失败/信息） |
| `--track` | 进度条、滑杆轨道 |
| `--chart-1..4` | 图表与速率曲线 |

状态色的**文字色**与**底色**都用同一 token，需要浅底时用
`color-mix(in srgb, var(--ok) 16%, transparent)`，不要再写死透明度色值。

### 2.3 本轮新增的颜色 token

| token | 用途 |
| --- | --- |
| `--file-video-*` / `--file-audio-*` / `--file-image-*` / `--file-doc-*` | 文件类型缩略图底色（1/2）与图钉前景色（fg），明暗各一套 |
| `--sn-g1a/g1b`、`--sn-g2a/g2b`、`--sn-g3a/g3b` | 资源嗅探缩略图三套渐变，明暗各一套 |
| `--sn-mini` | 嗅探缩略图上的迷你标记色 |
| `--poster-a/b/c/d` | 视频海报占位渐变（与主题无关） |
| `--overlay` / `--overlay-soft` | 海报上的时长/清晰度角标底色 |
| `--scrim` | 弹窗遮罩 |
| `--on-dark-fill` / `--on-dark-line` | 海报播放键的半透明填充与描边 |
| `--fg-inverse` | 深底上的白字（开关滑块、角标、关闭按钮 hover） |
| `--danger-close` | 窗口关闭按钮 hover 红 |
| `--brand-violet-*` / `--brand-azure-*` / `--brand-emerald-*` / `--brand-amber-*` | 设置页主题预览的三个色点；**固定品牌色**，不随当前主题变化 |

### 2.4 对比度（WCAG 2.1 AA，脚本实测）

口径：正文类（字号 < 18.5px，或 < 24px 且非粗体）≥ **4.5:1**；大字号 ≥ **3:1**；
图标/图形（17px 图钉、播放键）≥ **3:1**。半透明底先按父层合成，渐进取更差一端。
判定对象是 `src/styles.css` 的**当前 token 取值**，不是设计稿或旧基线。

| 角色 | 检查元素 | 字号 | 最低实测 | 全部 8 套 |
| --- | --- | --- | --- | --- |
| 正文 | 列表/详情正文 | 13px | 14.04:1 | ✓ |
| 次级文字 | 次级文字 | 12px | 6.24:1 | ✓ |
| 次级文字 | 弱化文字（含 11px 元信息） | 11–12px | 4.59:1 | ✓ |
| 强调文字 | 链接/选中导航 | 13px | 5.26:1 | ✓ |
| 强调文字 | 选中导航（11px，13% 强调底） | 11px | 4.57:1 | ✓ |
| 主按钮 | 白字常态 / 悬停 | 12px | 5.02 / 6.50:1 | ✓ |
| 状态徽标 | 下载中/排队中/已完成/需处理/已暂停/默认标签/嗅探标签 | 11px | 4.64:1 | ✓ |
| 文件类型色板 | 视频/音频/图片/文档图钉、嗅探小字 | 17px / 11px | 3.31 / 4.89:1 | ✓ |
| 海报与遮罩 | 时长角标、播放键 | 11px | 18.49 / 13.43:1 | ✓ |

规则：

1. 11px 只用 `--fg-2` / `--fg-3` / 状态色，且必须在**明暗 × 四套配色**全部 ≥ 4.5:1；
   四套明色的 `--fg-3` 各自独立取值（同一个值在不同底色上会差 0.2–0.3）。
2. 小字不用半透明前景（`opacity`）来"压暗"：合成后的实际对比度脚本算不到，等于绕过闸门。
3. 状态色只用于文字与同色 12–16% 淡底；淡底不要压第二种颜色的小字。
4. 新增或调整任何颜色 token，先跑 `node tools/Check-FwContrast.mjs`，不达标就改色，
   确实无法改的（例如纯装饰图形）写进本节"限制"并给出理由，不允许静默放过。

当前限制：无。8 套配色 × 24 个检查项全部达标（明细见
[docs/evidence/ui-tokens/contrast-v2.md](evidence/ui-tokens/contrast-v2.md)）。

## 3. 字体、字号与行高

### 3.1 字体族

```css
--font: -apple-system, "Segoe UI Variable Text", "Segoe UI", "PingFang SC",
        "Microsoft YaHei UI", "Noto Sans SC", system-ui, sans-serif;
--mono: "SFMono-Regular", Consolas, "Cascadia Mono", "Liberation Mono", monospace;
```

正文、按钮、输入框一律 `var(--font)`；日志、URL、尺寸数字、代码用 `var(--mono)`。
不要再写 `ui-monospace` 之类的一次性字体栈。

### 3.2 字号阶梯（6 档）

v1 曾把 9/10/10.5/11/11.5/12/12.5/13 这一串逐个命名，等于给现状拍照，不是规范。
v2 直接按**角色**合并成 3 档小字 + 3 档大字：

| token | 值 | 角色 | 典型位置 |
| --- | --- | --- | --- |
| `--fs-caption` | 11px | 元信息/徽标 | 分组标签、表头、时间戳、单位、角标、状态栏、`tag` |
| `--fs-body` | 12px | 次级文字 / 控件文字 | 行副标题、说明段落、按钮、输入框、下拉、chip、设置项标签 |
| `--fs-base` | 13px | 正文 / 导航项 / 行主标题 | `body` 默认、侧栏项、任务名、区块小标题 |
| `--fs-title` | 16px | 标题 | 卡片标题、弹窗标题、详情标题、视频信息标题 |
| `--fs-head` | 20px | 页面级强调 | 视图主标题、统计数值 |
| `--fs-display` | 28px | 展示级 | 视频页大速率数字 |

合并映射（v1 → v2），一次性做完，不留旧名：

| v1 | v2 | 说明 |
| --- | --- | --- |
| `--fs-2xs` 9 / `--fs-xs` 10 / `--fs-caption` 10.5 / `--fs-meta` 11 | `--fs-caption` 11 | 四档小字全部并入 11 |
| `--fs-sm` 11.5 / `--fs-body-sm` 12 / `--fs-control` 12.5 | `--fs-body` 12 | 控件与次级文字统一 12 |
| `--fs-body` 13 / `--fs-body-lg` 14 | `--fs-base` 13 | 14 那档只有"＋"字形，回落到正文 |
| `--fs-h3` 16 / `--fs-stat-s` 17 / `--fs-h2` 18 | `--fs-title` 16 | 17/18 没有独立语义 |
| `--fs-h1` 19 / `--fs-stat` 20 / `--fs-display-s` 26 | `--fs-head` 20 | 页面标题与统计数字同档 |
| `--fs-display` 30 | `--fs-display` 28 | 30 在 760 宽下会撑破大速率行 |

窄窗不再单独造 17/26 这类中间档：需要收小时换到**上一档**（`.stat .v` 20 → 16，`.big-speed` 28 → 20）。

### 3.3 行高（4 档）

| token | 值 | 用在哪 |
| --- | --- | --- |
| `--lh-none` | 1 | 单行角标、箭头图标、图标按钮 |
| `--lh-tight` | 1.1 | 大号数字（速率） |
| `--lh-base` | 1.6 | 正文基准（body）与所有多行文字 |
| `--lh-loose` | 1.9 | 连接日志 |

v1 的 1.55 与 1.65 是同一件事的两种写法（差 0.1 在 13px 上是 1.3px，肉眼看不出），
v2 合并为 1.6。行高只有这 4 档，**不要为了"挤一点"单独写 1.5**。

### 3.4 角色定档表（检查脚本据此判定）

每个角色绑定允许的档位集合。用了集合外的档位 = `role-font` / `role-height` 违规。

| 角色 | 选择器 | 允许字号 | 允许高度 |
| --- | --- | --- | --- |
| 行内紧凑按钮 | `.tbtn`、`.vp-dock button` | `--fs-body` | `--ctl-xs` |
| 次级按钮 | `.btn.sm`、`.chip`、`.mini-select`、`.modal-x`、`.ico` | `--fs-body` | `--ctl-sm` |
| 主按钮 | `.btn`（含 `.primary`/`.ok`/`.ghost`） | `--fs-body` | `--ctl-md` |
| 输入框 | `.field`、`.color-card`、`.select-wrap select` | `--fs-body` | `--ctl-md` |
| 导航项 | `.sb`、`.set-nav a` | `--fs-base` | `--ctl-lg` |
| 列表行 | `.task`、`.sn` | `--fs-base` | `--row-h` |
| 标题 | `.h1`、`.det-title`、`.vid-info h2`、`.big-speed` | `--fs-title` / `--fs-head` / `--fs-display` | — |
| 正文 | `body`、`.h2`、`.sec-h`、`.t-name`、`.brand-name`、`.update-ver` | `--fs-base` | — |
| 次级文字 | `.muted`、`.dim`、`.sec-d`、`.t-sub`、`.det-url`、`.kv`、`.conn-row`、`.sniff-url` | `--fs-body` / `--fs-caption` | — |
| 元信息/徽标 | `.tag`、`.q-badge`、`.update-badge`、`.dup`、`.stat .k`、`.stat .d`、`.list-head`、`.statusbar`、`.poster .dur` | `--fs-caption` | — |

规则：

1. 新组件先回答"它是哪个角色"，再从该角色的集合里选档；角色表里没有的组件，先在规范里加一行。
2. 同一角色出现第二个高度档就是"尺寸不一致"，必须并档——v2 已经把新建下载大输入从 36 并到 32。
3. 角色的后代元素（`.sb .n`、`.chip .c`）不算角色本体，按"元信息"自己约束。

## 4. 间距阶梯

**4px 网格，10 档**。v1 的 2px 基准（2/6/10/14 逐档）已删除——它让"差 2px"变成一种可接受的偷懒。

| token | 值 | 典型用途 |
| --- | --- | --- |
| `--space-4` | 4px | 图标与数字之间、极小间隙、开关内缩 |
| `--space-8` | 8px | 行内元素间隙、小标签内边距、控件内部横向内边距 |
| `--space-12` | 12px | 卡片内边距、侧栏内边距、侧栏项内边距 |
| `--space-16` | 16px | 主区域内边距、卡片之间、状态栏横向 |
| `--space-20` | 20px | 窄窗主区域内边距、大区块间距 |
| `--space-24` | 24px | 页面级内边距、设置页分区间距 |
| `--space-32` | 32px | 空状态与大区块分隔 |
| `--space-40` | 40px | 空状态纵向留白（小） |
| `--space-56` | 56px | 空状态纵向留白（主） |
| `--space-64` | 64px | 空状态纵向留白（大） |

合并映射：`--space-2`→4、`--space-6`→8、`--space-10`→12、`--space-14`→16（一律向上对齐到 4px 网格）。
间距整体略松 2px，是靠真实构建的多尺寸截图确认过的，不是纸面推算。

规则：

1. 先选档，再写布局；不要先写 13px 再找 token。
2. 同一组元素（列表行、设置行、卡片）用同一个档位，不要"这行 12、那行 16"。
3. 定位偏移（`top/right/bottom/left`）同样走阶梯；**几何派生值一律写成 `calc()`**，
   不再进例外清单：开关滑块位移 `calc(100% - var(--sw-knob) - var(--space-4))`、
   侧栏选中条 `calc(-1 * var(--space-12))`、轻提示离底 `calc(var(--shell-status) + var(--space-20))`、
   窄窗提示离顶 `calc(var(--shell-titlebar) + var(--space-8))`、
   批量条让位 `calc(var(--bulk-h) + var(--space-12))`。
4. 负间距用 `calc(-1 * var(--space-n))`，不写 `-12px`。

## 5. 圆角与描边

| token | 值 | 用途 |
| --- | --- | --- |
| `--r-xs` | 4px | 极小标记、标签、进度条、复选框、选中指示条端头 |
| `--r-sm` | 6px | 按钮、图标按钮、输入框、侧栏项、缩略图 |
| `--r-md` | 10px | 卡片、分段控件、提示条、列表行 |
| `--r-lg` | 14px | 大卡片、详情图标底板、弹窗 |
| `--r-pill` | 999px | 胶囊标签、开关轨道、顶部状态胶囊 |
| `--r-full` | 50% | 圆形（头像、圆点、开关滑块） |

v1 的 7/9/10 三个近似档（以及 2px）已合并：2→4、7→6、9→10，观感差异在 1px 内。

描边：`--bw` 1px 为默认；`--bw-strong` 1.5px 只用于 15px 复选框/单选与侧栏选中条（1px 在暗色下发虚）；
`--bw-scroll` 3px 只用于滚动条滑块与轨道之间的内缩，不用于普通边框。

写 `border` 时统一：`border:var(--bw) solid var(--line)`。

## 6. 控件高度与外壳尺寸

**4 档，按控件角色分配**（v1 的 9 档 2px 递进已合并：20/22→24、24→24、26/28→28、30/32→32、36/40→36）：

| token | 值 | 分配到的角色 |
| --- | --- | --- |
| `--ctl-xs` | 24px | 行内紧凑按钮（`.tbtn`、视口坞按钮）、开关轨道 |
| `--ctl-sm` | 28px | 次级按钮（`.btn.sm`）、chip、迷你下拉、弹窗关闭、标题栏图标按钮 |
| `--ctl-md` | 32px | 主按钮、输入框、主题色卡、新建下载面板 |
| `--ctl-lg` | 36px | 侧栏导航项 |

外壳：

| token | 值 | 用途 |
| --- | --- | --- |
| `--shell-titlebar` | 44px | 标题栏高度 |
| `--shell-status` | 30px | 状态栏高度 |
| `--shell-sidebar` | 246px | 侧栏宽度（断点内覆盖为 216 / 60 / 56） |
| `--bulk-h` | 54px | 批量操作条单行高度（12×2 内边距 + 28 控件 + 2 描边），列表区收缩量由它推导 |
| `--sw-w` / `--sw-knob` | 40px / 16px | 开关轨道宽与滑块直径，位移由 calc 推导 |

密度：`html[data-density="compact"]` 行高 56px、间隙 8px；`comfortable` 为 70px / 12px
（`--row-h`、`--gap`）。

**新增控件时先选角色，再选高度档**。不允许出现 26、30、34 这类高度；也不允许同一角色两种高度。

### 6.1 容器/装饰尺寸的角色档位

容器/装饰尺寸不写进 token 阶梯，但**不是随便写**：检查脚本按角色锁定固定档位集合，
用了集合外的值就报 `role-size`（v2.1 起不再记 info 放行）。响应式收窄的档也算在同一集合里。

| 角色 | 选择器 | 允许值 |
| --- | --- | --- |
| 列表缩略图 | `.thumb` | 40×40 / 34×34（窄窗） |
| 小缩略图 | `.thumb.sm` | 32×32 |
| 嗅探缩略图 | `.sn-thumb` | 44×30 / 34×24（窄窗） |

## 8. 图标尺寸

SVG 的 `width`/`height` 是属性，不能引用 CSS 变量，因此改用**离散白名单**：

`9 / 10 / 12 / 13 / 14 / 15 / 16 / 17 / 20 / 24`，且宽高必须相等。

- 9：排序箭头
- 10：极小箭头/角标
- 12：窗口控制、行内小图标
- 13–16：行内功能图标（默认 16，紧凑处 14/15，按钮内 13）
- 17：文件类型图标（40px 缩略图内）
- 20 / 24：空状态与品牌标识

新增图标若需要 18px，先在本节加档并说明用途，否则检查失败。

## 9. 常见错误对照

| 错误写法 | 正确写法 | 原因 |
| --- | --- | --- |
| `font-size:12.5px` | `font-size:var(--fs-body)` | 字号不走 token |
| `font:500 12px var(--font)` | `font:500 var(--fs-body) var(--font)` | 简写里也要用 token |
| `.sec-h{font-size:var(--fs-title)}` | `.sec-h{font-size:var(--fs-base)}` | 用了 token 但选错档（`role-font`） |
| `.btn.sm{height:var(--ctl-lg)}` | `.btn.sm{height:var(--ctl-sm)}` | 同角色尺寸不一致（`role-height`） |
| `.thumb{width:36px}` | `.thumb{width:40px}`（或 34px 窄窗档） | 容器尺寸不在角色档位里（`role-size`） |
| `.avatar{width:30px}` | `.avatar{width:26px}` | 同角色尺寸漂移（`role-size`） |
| `padding:0 9px` | `padding:0 var(--space-8)` | 间距不在 4px 网格 |
| `margin-top:7px` | `margin-top:var(--space-8)` | 同上 |
| `border-radius:6px` | `border-radius:var(--r-sm)` | 圆角不在阶梯 |
| `border:1px solid var(--line)` | `border:var(--bw) solid var(--line)` | 描边宽度走 token |
| `height:27px`（按钮） | `height:var(--ctl-sm)` | 控件高度不在阶梯 |
| `color:#fff` | `color:var(--fg-inverse)` | 颜色字面量 |
| `background:rgba(0,0,0,.65)` | `background:var(--overlay)` | 叠加层要 token |
| `style="height:6px"` | 加 `.bar.tall` 类 | 行内样式禁止字面值 |
| `<svg width="18" …>` | 用 16 或 20，或在第 8 节加档 | 图标尺寸白名单 |

## 10. 例外机制

v1 用例外清单兜住了 5 条"几何派生值"。v2 把这 5 条全部改写成 `calc()` 推导，
**当前例外 0 条**。这不是放宽规则，而是把"算出来的值"和"随手写的值"区分开：

- 能用 `calc(外壳尺寸 ± 阶梯值)` 表达的一律写成 calc，不进清单；
- 真正的例外只留给"CSS 里无法推导、必须与像素对齐的第三方尺寸"；
- 一条例外都没有时，`--strict` 才是真正紧的闸门。

流程（确实需要例外时）：

1. 在 `tools/fw-ui-tokens.exceptions.json` 加一条：`rule` + `file` + `match`（声明文本片段）+ `reason`。
2. `reason` 必须写清**推导关系**（"= 轨道宽 40 − 滑块 16 − 2×4"），不能只写"历史原因"。
3. 检查脚本统计每条例外的命中次数；**没命中的条目就是过期例外**，`--strict` 直接判失败。
4. 例外不是"不想改"的借口：能算出来就不许进清单。

## 11. 检查与发布闸门

```powershell
# 人读输出；有 error 时退出码 1
node tools/Check-FwUiTokens.mjs

# 机器可读（CI 归档、发布证据）
node tools/Check-FwUiTokens.mjs --json

# 发布用：过期例外也算失败
node tools/Check-FwUiTokens.mjs --strict

# 对比度：按当前 token 实算 8 套配色，不达标退出码 1
node tools/Check-FwContrast.mjs
node tools/Check-FwContrast.mjs --md      # 生成规范/证据里的表
node tools/Check-FwContrast.mjs --json    # CI 归档
```

- **CI**：`.github/workflows/release.yml` 在构建之前跑 `--strict` 与对比度检查，失败即中止发布。
- **发布检查清单**：`docs/发布检查清单.md` 的"界面设计 token 检查"项，打 tag 前必须通过。
- **新增/修改界面的 PR**：先跑检查；出现 `role-font` / `role-height` 说明选错档，
  出现 `role-size` 说明容器尺寸不在该角色的固定档位里，回到 6.1 节选，不要就地写一个新值。
