# 验证基线：离屏优先、不注入输入

本仓库所有自动化验证（截图、点击、按键、安装/卸载、扩展联调）默认按本文档执行。
新写脚本、改旧脚本都先对照第 4 节的自查项；违反第 2 节的硬规则就算验证结果无效。

## 1. 为什么定这条基线

验证脚本在开发者的真实桌面上跑。一旦为了「让脚本能点到」去移动光标、模拟点击或注入键盘，
代价由用户承担：正在打字的内容被打断、正在拖拽的文件被丢下、鼠标被抢走几秒。
这类代价与「验证有没有通过」没有关系，属于工具设计缺陷，不是必要成本。

离屏手段现在已经够用：WebView2 与 Chromium 都开 CDP，窗口内容用 `PrintWindow` 就能取，
Native 侧有窗口消息与 UIA。所以基线不是「尽量少打扰」，而是**默认完全不打扰**。

## 2. 硬规则

1. **默认离屏**：验证进程用隐藏窗口或最小化状态启动（`FW_SMOKE=1`、headless 浏览器），
   不把窗口抢到前台，不改 Z 序。
2. **不得占用输入设备**：禁止 `SetCursorPos`、`SendInput`、`mouse_event`、`keybd_event`，
   禁止模拟鼠标移动/点击，禁止把真实键盘事件注入桌面。需要按键就往目标窗口投递
   `WM_KEYDOWN` / `WM_KEYUP`；需要点击就用页面内点击或 UIA 的 Invoke/Pattern。
3. **需要前台的项目先报时长再合批**：确实拿不到前台就无法验证的场景（UAC 提权弹窗、
   托盘图标真实点击、系统级拦截提示），先说明预计耗时，把同类场景合并成一次执行，
   做完立刻让出前台，不留后台窗口。
4. **拿不到前台就如实标注**：写「未验证 + 原因」，不得用注入输入去凑一个通过。
   验证结果里「实测」与「代码层确认」必须分开写。

## 3. 允许的手段对照表

| 要做的事 | 用什么 | 现状 |
| --- | --- | --- |
| 取窗口画面 | `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT=2)`，按 `GetWindowRect`/`GetClientRect` 差值裁客户区 | [Capture-FwUiShots.ps1](../tools/Capture-FwUiShots.ps1) 已用 |
| 改窗口尺寸 | `SetWindowPos(..., SWP_NOZORDER)`，只改尺寸不动 Z 序 | 同上 |
| 页面内点一个元素 | CDP `Runtime.evaluate` 执行 `document.querySelector(sel).click()` | [Click-FwUi.mjs](../tools/Click-FwUi.mjs) 已用 |
| 需要指针语义（按下/移动/悬停/拖动、命中测试） | CDP `Input.dispatchMouseEvent`，须在脚本注释写明为什么不能用 `element.click()` | [Test-FwExtActivate.mjs](../tools/Test-FwExtActivate.mjs) 的浮动条点击 |
| 向窗口发按键 | `PostMessage(WM_KEYDOWN/WM_KEYUP)` | 需要时新写；目前未封装 |
| 点原生控件 | UIA `InvokePattern` / `LegacyIAccessiblePattern` | 需要时新写；目前未封装 |
| 隐藏/最小化窗口 | `ShowWindow(h, SW_HIDE/SW_MINIMIZE)` | 已用（不抬前台） |
| 观察窗口状态 | `IsIconic` / `IsWindowVisible` / `GetForegroundWindow` 比对 | 已用 |

## 4. CDP 输入事件的口径

`Input.dispatchMouseEvent` / `Input.dispatchKeyEvent` **判定为合规**。理由：CDP 的输入事件
只送进目标页面，由浏览器渲染进程处理，不移动真实光标、不进桌面输入队列，用户不会感知。
这条约束要管的是「占用用户的鼠标键盘」，不是「页面内不许有指针事件」。

但按用途分开用：

- **单纯点一个元素**：一律 `element.click()`。它走 DOM 事件分发，够用且不依赖坐标，
  元素被滚动、被遮挡都不影响。
- **需要指针事件语义**时才用 `dispatchMouseEvent`：按下/移动/悬停/拖动的中间状态，
  或者要验证「用户真的点得到」——即坐标能命中目标元素、没被别的元素盖住。
  这时 `element.click()` 会绕过命中测试，即使按钮被遮挡也会"通过"，反而验不出问题。
  用了就在脚本里写清这一段是哪种情况。

## 5. 新脚本自查项

写或改验证脚本时逐条过：

- [ ] 启动被测程序时有没有设 `FW_SMOKE=1`（或等价隐藏手段），有没有误用 `ShowWindow(SW_SHOW)`。
- [ ] 有没有出现 `SetCursorPos` / `SendInput` / `mouse_event` / `keybd_event` / `CopyFromScreen`；
      有就换成 `PrintWindow`、页面内点击或窗口消息。
- [ ] 点击是不是优先 `element.click()`；用了 `dispatchMouseEvent` 的，注释写清为什么需要指针语义。
- [ ] 需要原生按键时走的是 `WM_KEYDOWN`/`WM_KEYUP` 而不是真实键盘注入。
- [ ] 必须前台的个别步骤是否已报时长、是否合批、是否在结束时把窗口还原/关闭。
- [ ] 拿不到前台的项是否写成「未验证 + 原因」，而不是用一个近似手段当成通过。

## 6. 历史

本次改动前，`tools/Capture-FwUiShots.ps1` 用 `SetCursorPos` + `mouse_event` 点侧栏
（会真实移动并点击用户鼠标）、用 `SetForegroundWindow` + `CopyFromScreen` 截图
（会抢前台且被遮挡时截到别人的窗口）。已改为 CDP 页面内点击与 `PrintWindow` 离屏截图，
见提交「验证改为纯离屏、不注入输入」。
